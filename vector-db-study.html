벡터 DB 도입 설계 케이스 스터디

약 1시간 30분 · 단일 AI 대화 세션에서 도출

벡터 DB/임베딩 사전 지식이 전혀 없는 상태에서 AI(Claude)와의 대화만으로 개념 이해 → 기술 선택 → 테이블 설계 → 데이터 흐름 → 인프라 판단 → 운영 고려사항까지 도출한 설계 초안입니다.

이 문서는 구현 완료 프로젝트가 아닌 설계 초안으로, 신규 기술을 빠르게 소화하고 구조를 잡는 판단 과정을 보여주기 위한 케이스 스터디입니다.

배경

리뷰 키워드 유사 매칭이 필요한 이유

배달 플랫폼 SaaS리뷰 키워드 통계유사 표현 매칭
문제
  • 기존 시스템은 키워드를 정확 일치(exact match)로만 조회
  • 리뷰에서는 같은 메뉴를 다양한 표현으로 언급 ("후라이드", "바삭한 치킨", "후치")
  • 정확 일치로는 유사 표현을 잡지 못해 키워드별 통계가 부정확
기술 선택지 비교
판단

LIKE는 글자가 겹쳐야만 찾고, GPT는 정확하지만 비용이 수십 배 높다. 벡터 검색은 의미 기반으로 유사 표현을 잡으면서 비용은 GPT 대비 수십 배 저렴하다.

키워드 정규화 전략

문제GPT 추출 키워드 중복

리뷰마다 "후라이드", "후라이드치킨", "프라이드치킨"이 각각 추출되면 통계가 분산됩니다.

해결벡터 유사도 기반 자동 정규화

추출된 키워드를 임베딩 → 기존 키워드와 유사도 비교 → 임계값 이상이면 기존 키워드에 연결, 미만이면 신규 등록합니다.

인프라 판단

검토벡터 검색 대상이 뭔가?

리뷰 수십만 건을 전부 벡터로 저장하면 DB 부하 발생. 키워드 수백 건만 벡터로 저장하면 부하 무시 가능.

결론DB 분리 불필요

벡터 검색 대상이 키워드 수백 건이므로 기존 PostgreSQL RDS + pgvector 확장만으로 충분. 별도 인프라 추가 없음.

흐름

2단계 비동기 처리 — 등록과 조회

동기: 리뷰 저장비동기: 키워드 추출 + 매칭서비스 품질 보호
리뷰 등록 시
조회 시
  1. 1검색어 입력 또는 키워드 선택
  2. 2검색어 임베딩 생성
  3. 3keyword 벡터 검색 (수백 건 대상)
  4. 4연결 테이블 INNER JOIN → 리뷰 조회
  5. 5GROUP BY → 키워드별 건수/평균 점수
  6. 6UI 키워드 필터링 (X 버튼 = WHERE IN 변경)

조회 시 벡터 검색은 키워드 수백 건 대상으로만 발생하고, 이후 리뷰 조회와 통계 집계는 전부 일반 SQL입니다.

경계

벡터가 관여하는 영역과 관여하지 않는 영역

핵심 설계 판단기술 경계 정의
판단

벡터는 입구에서 "어떤 키워드가 관련 있는지" 판별하는 역할만 한다. 안에 들어오면 전부 기존 SQL이다.

벡터가 관여하는 지점 — 딱 2곳

등록 시키워드 정규화

추출된 키워드 → 임베딩 → 기존 키워드와 유사도 비교. 비교 대상: 키워드 수백 건.

조회 시유사 키워드 추출

검색어 → 임베딩 → 키워드 테이블에서 유사 키워드 추출. 비교 대상: 키워드 수백 건.

벡터가 관여하지 않는 지점 — 나머지 전부
  • 매칭 결과 저장 → 연결 테이블 INSERT
  • 리뷰 목록 조회 → INNER JOIN
  • 키워드별 건수/평균 점수 → GROUP BY
  • 키워드 삭제 → 연결 테이블 DELETE
  • UI 키워드 필터링 → WHERE IN 조건 변경
  • 리뷰 원본 관리 → 기존 로직 그대로

AI 제안3단계 분리

"리뷰 저장(동기) → GPT+임베딩(비동기) → 키워드 매칭(비동기)으로 나누자"

본인 판단2단계로 합침

"키워드 매칭이 ~10ms면 별도 큐로 나눌 필요 없다. GPT+임베딩 끝나면 바로 매칭하자" → 실측 데이터 기반 구조 단순화

결과 — 도출된 역량
  • 기술 추상화 — 복잡한 개념을 자기 언어로 단순화
  • 경계 인식 — 새 기술의 영향 범위를 빠르게 파악
  • 구조 설계 — 정규화, 데이터 흐름, 인프라 판단을 동시에 도출
  • 실용적 판단 — 원칙에 매몰되지 않고 데이터 기반으로 조정
  • 운영 감각 — 임계값 외부 관리, 원본 보존, 재매핑 전략
  • AI 활용 — AI를 답을 받는 도구가 아닌 설계 검증 파트너로 활용

이 문서는 구현 완료 프로젝트가 아닌 설계 초안입니다. 신규 기술을 빠르게 소화하고 구조를 잡는 판단 과정을 보여주기 위한 케이스 스터디입니다.
